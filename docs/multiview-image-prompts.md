# 用于本机多视角重建的图片提示词

## 先说明限制

当前神庙三图的侧面相机匹配失败，不能仅据此断定三张原图不合格。重复的双塔、砖纹、遮挡、不同视角中的结构不一致，都可能使自动匹配产生歧义。图像看着像同一套模型，并不证明空间几何一致。

最可靠的输入是同一个已有三维场景导出的三个视角：模型保持不动，只移动相机。若已持有该场景的 GLB，直接导入 GLB 可以省去从图片估计几何的环节。

以下提示词用于提高 AI 图片的一致性，不保证三维一致或可拼装。先附上同一张原始参考图；每次生成都继续引用它和之前生成的视图，不要开三个独立任务重新设计。输出三个独立文件，不能把拼贴图直接作为一张视图上传。

## 三张图共用的提示词

```text
以我上传的神庙参考图为同一个固定物体，生成用于多视角三维重建的图片。

保持模型的整体比例、底座宽深、双塔间距与高度、塔顶形状、台阶数量和坡度、中央壁龛、雕像、左右两个火盆、左前方树木、地面铺装完全一致。物体、零件和装饰都保持原位，颜色、材质和纹理保持一致。只改变相机位置，不重新设计模型，不把正面装饰复制到侧墙，不增加或移除结构。

使用普通透视相机，固定焦距 50 mm；相机始终看向整个模型的中心。不是鱼眼，不是正交工程图。使用同样的浅灰纯色背景、柔和均匀照明、轻微阴影；不要景深、模糊、强反光、文字、标签、水印、尺寸线或拼贴边框。

整个物体和底座完整入镜，不裁切；主体最长边占画面约 75%，四周保留空白。输出一张 1024 × 1024 的独立图片。保留自然可见的墙角、开口、台阶与纹理，供不同视图对应。

本次只按下面指定的相机视角生成。
```

“75%”“50 mm”和下面的角度是拍摄方案建议，不是软件通过校验的保证条件。

## 第 1 张：上传到「正视」

在共用提示词后追加：

```text
相机位于神庙正前方，水平偏转 0°，向下俯拍约 15°。清楚显示两座塔、中央壁龛与雕像、两个火盆、完整台阶和左前方树木。底座左右边缘完整可见。
```

## 第 2 张：上传到「侧视」

仍附上原参考图及第 1 张，在共用提示词后追加：

```text
保持同一个物体，仅把相机移动到神庙右前方约 45°，向下俯拍约 15°。同时显示正面与右侧，保留中央台阶、入口、两个塔和底座前右角等与正面图可对应的结构。不要生成完全看不到正面的纯右侧图。正面与右侧的交界墙角必须清楚。雕像和火盆不能换位置，左前方树木仍在原位置。
```

## 第 3 张：上传到「俯视」

仍附上原参考图及前两张，在共用提示词后追加：

```text
保持同一个物体，仅把相机移动到神庙前上方，水平偏转 0°，向下俯拍约 60°。同时显示塔顶、地面铺装、台阶和部分正面，保留与第一张可对应的结构。这是透视斜俯视图，不是垂直正交俯视图。底座深度、双塔间距、雕像位置、两个火盆和树木位置必须与之前的图一致。
```

这三张图在工作台中选择「同一模型的普通实拍照片 / 透视渲染图」，不要选择「正交渲染图 / 无透视三视图」。

## 生成后先核对

- 三张图中的双塔、台阶、壁龛、雕像与火盆数量一致。
- 同一墙角、开口和砖纹能在相邻视图中对应，不能随相机旋转移动或变形。
- 雕像与树可能被遮挡，但不能迁移到别的位置。
- 右侧图没有把正面壁龛重新生成在右墙上。
- 底座比例和塔的深度一致，没有某张图突然变薄或变厚。

满足这些可见条件仍不能证明完整三维一致。如果持续匹配失败，应回到同一个三维场景渲染，而不是不断修改提示词并反复推理。

参考：[MapAnything 官方说明](https://github.com/facebookresearch/map-anything)、[COLMAP 拍摄指南](https://colmap.github.io/tutorial.html)。上述具体相机角度是针对当前输入流程的建议，不是官方规定。
