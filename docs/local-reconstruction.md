# 本机重建

当前 Mac 已安装，双击项目根目录的 `启动本地重建.command`。启动后打开 http://localhost:3000，上传图片，生成并检查三维草稿，再转换为积木。保持终端开启。停止使用时在终端按 Ctrl+C。

在线网站不能直接调用另一台电脑的 GPU。无需账号的重建只在这台电脑的本机工作台运行；可把生成的 GLB 下载后导入在线网站。原始 GLB 不带照片纹理。V12 会在本机重建完成后，用去背景参考图自动恢复可见区域的积木配色；背面颜色按高度区间的主要材质推测。导入 GLB 后也可上传对应参考图并点击“按参考图恢复配色”。原始 GLB 下载不包含该配色；积木模型、清单和说明书包含配色。

## 本机依赖

- Hunyuan3D-Swift 源码：https://github.com/ZimengXiong/Hunyuan3D-Swift ，使用提交 `292331f4d26ddb80b9dcea6bcb5629ff82f12b82`。Swift 源码 MIT，模型和算法保留各自许可证。
- mlx-swift 0.31.4，底层 MLX 0.31.1；Swift Numerics 1.1.1。
- 权重：https://huggingface.co/zimengxiong/hunyuan3d-mlx-shape-small ，`model.fp16.safetensors` 3,819,958,234 字节，SHA-256 `3cc66f3bea33e4062b7dbc875ffe1d70c4888914aec3e91b60f94e9bd01b522b`。
- Metal 运算库来自 PyPI 的 `mlx-metal 0.31.1` macOS 26 ARM64 官方 wheel，SHA-256 `e7324b7c56b519ae67c025d3ced07e5d35bc3a9f19d4c45fe4927f385148c59e`。从 wheel 提取 `mlx.metallib`，与可执行文件放在一起。这样不需要另装完整 Xcode 的 Metal 编译器。
- `scripts/prepare-local-image.swift` 使用 macOS Vision 的前景掩模，并输出透明 PNG。没有向外部服务发送图片。

本轮仅使用 shape 小模型；没有下载或运行需要更大内存的 paint 纹理模型。完整模型的商用/分发应另查上游模型许可证，源码 MIT 不等于权重也采用 MIT。

## 在另一台 Apple Silicon Mac 安装

需要 Swift 6、Node.js 22.13+、macOS 14+、约 16 GB 内存。当前提取的 Metal 库针对 macOS 26；其他系统请选择对应的官方 wheel。

1. 从上述提交获取 Hunyuan3D-Swift，运行 `swift build -c release -j 4`。保留其上游许可证。
2. 把生成的 `hy3d` 复制到本项目 `work/local-3d/hy3d`；把匹配系统的 `mlx.metallib` 放在同一目录。
3. 从上述权重仓库下载 `model.fp16.safetensors` 和 `config.yaml` 至 `work/local-3d/weights/`，核对文件大小与哈希。首次需要约 4 GB 下载。
4. 在项目目录执行 `swiftc scripts/prepare-local-image.swift -o work/local-3d/prepare-image`。
5. 运行 `npm run local`。此模式的重建端点只接受本机请求，任务一次运行一个。

本次网络到 GitHub/Hugging Face 原站不稳定，源码依赖改用相同固定版本的 GitHub codeload，模型使用 Hugging Face 镜像，Metal wheel 使用 PyPI 镜像；两个大文件均与上游元数据中的 SHA-256 核验一致。临时源码位于系统临时目录，重启可能清理；已复制的可执行文件、Metal 库、权重在 `work/local-3d/`，正常启动不依赖临时源码。

## 已验证与限制

神庙照片经过 Vision 去背景后成功生成 163,004 个三角面的 GLB，正面与侧面可辨双塔、台阶、门内雕像、前方树木。HTTP 提交、状态查询和 GLB 下载也成功。三维网格不是乐高零件清单：需要第二阶段按真实网格体积转换，仍会损失细节并添加支撑，不能保证真实拼装稳定或每种零件颜色有库存。

无浏览器截图/交互测试。本轮用独立网格渲染、真实图片推理、HTTP 接口、转换与导出验证。

V12 提供 28 / 36 / 48 凸点尺寸，默认 36。选择高精细会增加零件数。自动光面收口只替换没有上层连接的表面，保留实际高度和承托；可关闭“减少阴影杂色”后重新配色。刷新工作台可加载更新；本机开发服务会在插件代码变化时自动重启，重启后旧任务凭证不再有效，可导入此前下载的 GLB 继续。

V15 在草稿就绪后自动识别并放置目录组件（火盆按颜色，枝叶树按形状，人物放在两个火盆之间的入口），不需要手动选点。放置会搜索邻近落点并剔除装不上的组件，因此转换一定返回成品；被跳过的数量写在状态栏与说明书说明里。未见表面按高度区间取主要材质色，深色开洞不再参与该估计，背面不会出现正面门窗的黑色方块。开启「减少阴影杂色」时，照片里的阴影与砖缝会整体并入主材质，近黑的中性色按深灰处理，不会在墙上留下黑色或深棕的错色块；关闭则保留照片明暗。实测这张神庙参考图配色的网格（158,744 三角面，48 凸点）：放入 2 个火盆、1 棵树与 1 个人物，全部通过装配检查，8,211 块零件（8,034 块沙色）。人物与树的识别仍是猜测；配色按轮廓对齐，网格又是 AI 近似，门窗位置无法与照片逐块对齐，成品需要人工复核。

V18 修好了本机重建里"树不见了"的问题：调色板没有橄榄绿，橄榄绿的树冠会被量化成脚下的沙色，而"低矮深色小块＝树"的兜底猜测又依赖树冠在当前分辨率下够不够暗 —— 界面把参考图缩到 320 px 后树冠变浅，猜测随之消失。现在"是不是叶子"在**照片上**判断（`R − G ≤ 10 && G − B ≥ 12 && 30 ≤ max ≤ 210`，即橄榄绿），结果按面记在 `mesh.features` 上，组件识别先看它、再看砖色。实测同一张神庙参考图与同一个本机网格（173,648 三角面，48 凸点，320 px 参考图）：修复前 3 个候选（2 火盆 + 1 人物）、成品无树；修复后树冠是第 1 个候选（颜色识别，锚点 x 0.092 / z 0.931），4 件组件全部落座，装配检查通过，离线渲染的树干与树冠落在参考图同一位置。判据读照片，图中任何暖调暗绿都可能成为枝叶候选，仍需人工复核。

## 本机三视图联合重建（2026-09-30）

工作台「三视图」默认选择透视照片 / 渲染图，三张图片一起进入独立的 MapAnything MLX 引擎。先估计三视角相机、深度与世界坐标，再在共同坐标系融合三维体积，显示草稿；用户检查后才转换积木。单图 Hunyuan3D mini 保留原流程。三图不会拼成一张图片，也不会分别生成三个模型再当成联合重建。

- 引擎源码：[mlx-spatial](https://github.com/appautomaton/mlx-spatial)，固定提交 `d2cc98ef7fb2166dc7e3b826b487e80f6f5027dc`。使用其 MapAnything 图像联合推理路径，不需要 CUDA。
- 权重：[facebook/map-anything](https://huggingface.co/facebook/map-anything)，4,914,062,480 字节，SHA-256 `981f060c64664dff3272b5f5a823d350abe71a2f144444db4cfc325f3ed5a3a0`。
- 安装：`sh scripts/setup-local-multiview.sh`；使用隔离的 Python 3.13 / MLX 0.32.3 环境。运行 `work/multiview-engine/.venv/bin/python scripts/test-multiview-fusion.py` 检查融合和相机检查。
- 本机服务接收三张 `{axis,image}`；输出一个 GLB 和相机检查报告。图像仅交给本机推理，安装时需要下载开源源码和权重。
- 颜色来自三视图观察到的表面，导出 glTF 顶点颜色时转换到线性空间，避免重复做 sRGB 转换而变白。
- 自动检查正面与侧面 / 俯视估计相机方向的差异。小于 20° 时提示匹配疑似失败，并禁止积木转换。该阈值只是基本异常检查，不证明几何准确。
- 未观察到的背面和内部体积仍需闭合推断；网格闭合、碰撞与连接检查不等于实物稳定性或说明书每步可操作性验证。

真实验证使用用户提供的神庙正面、侧面与斜俯视 PNG：三图联合推理与 GLB 输出完成，133,502 个三角面。侧面被错误估计成接近正面的方向，融合出现变形，因此此组输出应由相机检查拦截，不能认定为合格积木成品。合成相机 / 深度立方体回归验证闭合、颜色以及俯视深度确实影响融合体积。未执行浏览器交互验证。

正交轮廓求交作为另一个草稿选项保留，增加连通性和轮廓保留检查；透视图默认不走该选项。轮廓检查通过也不代表能恢复壁龛、雕像等内部可见细节。

本次验证：`npm test` 156 项通过，融合 Python 回归 3 项通过，`npm run typecheck` 与 `npm run build` 通过；真实 HTTP 三图提交、轮询、鉴权 GLB 下载和相机拦截通过。全仓 `npm run lint` 仍有已有 React Compiler、原生图片与测试 promise 规则等错误，未通过；本次新增请求测试的 promise 已显式处理。
