### 第一批实现

- 在隔离的 `work/semantic-engine` 运行 [Grounding DINO tiny](https://huggingface.co/IDEA-Research/grounding-dino-tiny) 对象检测和 [SlimSAM](https://huggingface.co/Zigeng/SlimSAM-uniform-77) 轮廓分割；使用模型作者公开权重，不调用付费 API。下载固定 revision 的 safetensors，记录文件哈希和运行库版本；推理只读本机文件且禁用联网。
- 输入保持原坐标，多尺度窗口识别小物体，并对同类别重复框去重。检测器输出原始文本匹配评分，分割器输出 mask IoU 估计，两者都不是经过本项目校准的概率。
- 身份、形状匹配、安装位置分别检查。颜色/壁龛规则只在学到的实例内补充安装证据，不再独立授权自动替换。
- “statue” 容易覆盖马形雕塑、头像和帽子。本批人物目录件需要同一位置的人体查询支持；不满足条件时保留源几何。树与火焰也必须有模型实例与实际轮廓。
- 修复主视觉兜底绕过身份检查的问题：`mustRepresent` 不能授权一个身份未确认的自动候选生成新人物。
- 自动替换失败、模型未配置或运行失败时保留源几何，并向用户显示原因。手动明确添加组件仍可使用。
- `/api/scene-analysis` 在本机模式执行识别，校验 origin、尺寸和像素值；并发相同输入共享任务。缓存同时绑定输入、权重清单和运行脚本指纹。托管环境尚未部署视觉服务，返回未配置状态，不回退到颜色自动替换。
- 原有 Temple surface 测试改为读取仓库内压缩 fixture，去掉对忽略的 `outputs/` 文件的依赖。保存真实模型输出作为确定性正例；单元测试不下载权重。

### 验证

- 六张旧基准图复用原三维 GLB，实际重新执行本机视觉检测和当前积木转换；输入、原生网格、识别引擎和转换代码指纹都记录在 `benchmarks/image-semantic-2026-10-01.json`。
- 禁止组件误安装均为 0。没有通过“关闭所有组件”实现：神庙雕像、两只火盆和树继续生成；小屋实际提交 1 个树组件，另一树候选安装失败，保留其源网格。
- 神庙正例涵盖标准档实际失败草稿及旧神庙 28/36/48；雕像可见，火盆底座四个 socket 均接上主体 studs。
- `npm test`：164 通过；`npm run typecheck`、`npm run build`：通过。新增模块的定向 lint 和 Python 语法检查通过。
- 真实本机 HTTP 路径返回 200：首次 8,789 ms，缓存重放 8 ms；两次都检测到两处火焰。这是 API 验证，没有宣称浏览器截图验收。

### 当前限制

这批解决了已有基准中的错误组件替换，**没有修好雕像后墙、通用表面、承重或说明书规划**。基准仍是六张干净样例图，不是独立真实照片集。本机检测模型仍有错标签；当前查询类别和身份支持规则不是通用零件编号识别器。阶段 2 必须继续从网格草稿构建平面、曲面、开口和材质区域，不能把这些通过记录包装成官方套装级质量。

完整设计依据见 `product-quality-audit-2026-09-30.md`。该审计是修改前的历史基线，本文件记录实施状态。

## 本机安装和复现

```sh
sh scripts/setup-local-semantics.sh
npm run local
python3 scripts/fetch-benchmark-images.py
npm run benchmark:images
```

已有模型缓存时只重跑识别/转换；`--native` 仅用于没有原生网格缓存的输入。可用 `--scene-dir=outputs/identity-calibration` 重放本轮实测识别记录，记录必须与当前运行脚本、输入像素和权重清单指纹一致；不允许用不匹配的记录让基准通过。

网络需要代理时，安装脚本读取 `BRICKFORM_SEMANTIC_PROXY`；下载中断可续传，未完整验证的权重不会生成 ready 状态。模型权重与个人图片缓存不提交到仓库。
