### 第一批实现

- 在隔离的 `work/semantic-engine` 运行 [Grounding DINO tiny](https://huggingface.co/IDEA-Research/grounding-dino-tiny) 对象检测和 [SlimSAM](https://huggingface.co/Zigeng/SlimSAM-uniform-77) 轮廓分割；使用模型作者公开权重，不调用付费 API。下载固定 revision 的 safetensors，记录文件哈希和运行库版本；推理只读本机文件且禁用联网。
- 输入保持原坐标，多尺度窗口识别小物体，并对同类别重复框去重。检测器输出原始文本匹配评分，分割器输出 mask IoU 估计，两者都不是经过本项目校准的概率。
- 身份、形状匹配、安装位置分别检查。颜色/壁龛规则只在学到的实例内补充安装证据，不再独立授权自动替换。
- “statue” 容易覆盖马形雕塑、头像和帽子。本批人物目录件需要同一位置的人体查询支持；不满足条件时保留源几何。树与火焰也必须有模型实例与实际轮廓。
- 修复主视觉兜底绕过身份检查的问题：`mustRepresent` 不能授权一个身份未确认的自动候选生成新人物。
- 自动替换失败、模型未配置或运行失败时保留源几何，并向用户显示原因。手动明确添加组件仍可使用。
- `/api/scene-analysis` 在本机模式执行识别，校验 origin、尺寸和像素值；并发相同输入共享任务。缓存同时绑定输入、权重清单和运行脚本指纹。托管环境尚未部署视觉服务，返回未配置状态，不回退到颜色自动替换。
- 原有 Temple surface 测试改为读取仓库内压缩 fixture，去掉对忽略的 `outputs/` 文件的依赖。保存真实模型输出作为确定性正例；单元测试不下载权重。

### 第二批：有证据的壁龛几何

- 新增 `DesignGeometry`：网格/参考共同支持的平面、图像边界支持的开口、局部材质及最终零件约束检查。先改变目标几何再排砖，不新增神庙模板。
- 按可见方向法线、三角面积加权深度共识和图像覆盖拟合后墙；排除雕像轮廓，区分整图和局部裁剪 mask。缺少平面或材质证据时保留原几何并记录原因。
- 用参考入口边界与观测到的前立面确定空腔。删除固定 10 凸点开口上限和“安装点后退 3 凸点”的后墙坐标。前景火盆空间独立保留，不要求它包含在后方空腔内。
- 后墙整理成连续两凸点厚实体，并由局部较亮墙面决定材质；只修改声明的区域。阴影材质属于明确的设计推断，不能从单图证明真实零件颜色。原神庙后墙选深沙色，新神庙选沙色；其他灰色装饰保留。
- 跨梁跟随开口，用现有目录的多层薄板拼接支持 11–16 凸点。替换梁下的原始屋顶碎片，覆盖奇数深度最后一列；清理范围包括真实入口开口。连接检查通过不代表跨梁承重经过实物测试。
- 在排砖、优化和组件安装之后检查墙面每个目标单元、区域配色和空腔占用。缺口、杂色或补柱出现时回滚该方案。

- 六张跨类别图再次完成转换，禁止组件误安装仍为 0；记录在 `benchmarks/image-geometry-2026-10-01.json`。这是缓存的原生网格/真实识别记录重放，没有重复执行原生三维推理。

### 第三批：先声明平台，再选择铺面零件

- `platform-design.ts` 从低位、朝上的三角面拟合平台，使用面积共识和残差门槛。只有实际观测覆盖、接近该平面、已有实体基础的列才能进入目标区域；帽子、动物和头像不能只因位置低就被当成地面。
- 平台计划在体积转换后计算一次，组件候选共用。替换原有“相邻八格判断孤立一层噪声”的修补；可纠正浅层多板误差，不把整块边界框填平。
- 真实抬升面、台阶、较高底座和贯通孔不纳入目标区域。局部图案的原表面颜色跟随高度校正保留；本批没有把全地面的灰色改成沙色。
- 只有声明的展示铺面可以把暴露的支撑顶面换成光面板；连接组件的安装面仍保留 studs。跨越目标区域边界的支撑件分割处理，区外的连接面保留。
- 最终零件审计检查目标列无缺口、顶面同高、无不需要的 studs。开口和组件引入的覆盖区域显式排除，检查发生在优化与组件安装之后。
- 两份真实神庙 × 三档共检查 2,784 列，校正 356 列；声明区域的缺口、高差与裸露凸点均为 0，雕像和两只连接火盆仍保留。记录在 `benchmarks/platform-2026-10-01.json`。这是局部平台约束，不能说明整块地面已精确还原；目标区域之外的小凸起仍可能保留。
- 六类图片再次重放完整转换，误装组件为 0。小屋 28/48 两档平台通过（分别检查 120/313 列）；另外五类不拟合平台。记录在 `benchmarks/image-platform-2026-10-01.json`。复用缓存网格与真实识别记录，没有重复运行三维推理。
- `npm test`：179 通过；类型检查、构建、新模块定向 lint、离线渲染脚本语法检查通过。

### 六类成品的外观复核：仍不合格

本批用真实目录零件和最终姿态离线渲染并检查六张图，**六张都仍按草稿处理**。这与“误装组件为 0”“连接通过”是不同的验收条件。

| 输入 | 当前主要外观缺口 |
| --- | --- |
| 小屋 | 屋顶还是阶梯体素面，白灰补丁和零件分布杂乱 |
| 机车 | 车身下方的长支撑柱/填充破坏负空间，轮组没有转成真实机构 |
| 马 | 身体和头部下方的支撑形成墙状体积，遮住腿部空间；曲面和配色仍碎片化 |
| 头像 | 长支撑延伸到基座，照片暗部成为异色材料，表面阶梯明显 |
| 帽子 | 帽檐/帽身仍是体素近似，装饰颜色碎片化 |
| 人物 | 小附属结构被块状表面和支撑遮住，轮廓与材质细节不足 |

这批检查进一步确定：`finishModel()` 为缺少下方连接的砖寻找竖直支撑路径，`optimizeAestheticPacking()` 只能删除部分冗余支撑，无法把悬挑主体重新设计为内部跨梁/子装配。因此，下一批必须对负空间与支撑可见性设置约束，再进行区域构造和装配设计。不能通过删掉支撑得到一个无法连接的漂亮模型，也不能通过填满空隙把错误外形包装成“可拼搭”。

离线图片位于 `outputs/platform-calibration/<case>-28.png`。神庙平台的顶视/立体图位于同目录 `standard-48-{top,hero}.png`。这些不是浏览器截图或实物试拼。源图仍是公开引擎样例，广泛独立图片与真实试拼验收尚未进行。

### 当前限制

已解决已有基准中的错误组件替换，并整理两份神庙入口后墙及有面积证据的平台；**通用表面、完整地面铺面与材质、背面布局、支撑构造、承重和说明书规划仍未完成**。基准仍是六张干净样例图，不是独立真实照片集。本机检测模型仍有错标签；当前查询类别和身份支持规则不是通用零件编号识别器。阶段 2 必须继续扩展到通用平面、曲面、开口和材质区域，不能把这些通过记录包装成官方套装级质量。

完整设计依据见 `product-quality-audit-2026-09-30.md`。该审计是修改前的历史基线，本文件记录实施状态。

## 本机安装和复现

```sh
sh scripts/setup-local-semantics.sh
npm run local
python3 scripts/fetch-benchmark-images.py
npm run benchmark:images
```

已有模型缓存时只重跑识别/转换；`--native` 仅用于没有原生网格缓存的输入。可用 `--scene-dir=outputs/identity-calibration` 重放本轮实测识别记录，记录必须与当前运行脚本、输入像素和权重清单指纹一致；不允许用不匹配的记录让基准通过。

网络需要代理时，安装脚本读取 `BRICKFORM_SEMANTIC_PROXY`；下载中断可续传，未完整验证的权重不会生成 ready 状态。模型权重与个人图片缓存不提交到仓库。
