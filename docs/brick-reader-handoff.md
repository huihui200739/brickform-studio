# 正面图纸识别（B 路线）交接说明

最后更新：V17 收尾。仓库状态：`npm test` 75/75、`tsc --noEmit` 干净、`npm run build` 通过。

## 1. 这条路线在做什么

参考图本身就是**乐高模型渲染图**时，不要去猜三维体积，而是**把砖块读出来**：
凸点周期 → 凸点间距 → 网格锚定到轮廓 → 按接缝切成砖块矩形 → 每个凸点 × 薄板格取色 → 交给现有装配器生成可拼装模型。

与另外两条路线的关系：

| 路线 | 输入 | 几何来源 | 状态 |
|---|---|---|---|
| 单图重建 | 一张任意照片 | Hunyuan3D 推测 + 自动放组件 | ✅ 可用 |
| 三视图重建 | 正交正/侧/俯三图 | 轮廓求交（确定性） | ✅ 可用 |
| **正面图纸** | 一张**正对**的乐高模型图 | **读砖块**（确定性） | ⚠️ 见第 4 节 |

## 2. 管线（`lib/brick-reader.ts` → `readFront`）

1. `referenceMask` 取主体轮廓与包围盒 → `left/right/top/bottom`
2. **凸点间距** `studPitch()`：按 18 条水平带分别做自相关，取相关性最强的那条带的周期（只有能看到凸点的水平面才有这个周期，通常是底板顶面）
   - 置信度 < 0.35 时抛错，界面要求手填正面宽度
3. **网格锚定轮廓**：`columnAt(k) = left + k*pitch`、`rowAt(k) = top + k*plate`，不搜索相位
   - 理由：正对视图的最外圈凸点就是外形，搜相位只会得到偏一格的答案
   - `plate = pitch * 0.4` **必须保持小数**（取整会让高立面漂移近半格）
4. **行分段**：`rowLine[k]` 为该薄板行是否是接缝，阈值 = 该段最强接缝 × 0.25；短于 3 薄板的分段并回邻段
5. **列分段**：在每一段内部单独判定垂直接缝（`joint()`），扫描整段但**跳过"整行都暗"的行**（那是横向边界，不是垂直接缝）
6. **取色**：每个凸点 × 薄板格独立取色（投票取众数，只采格子内部），孤立浅色格并回邻域
7. `blueprintToModel()`：正面两层体素刷读到的颜色，其余填主材质，`finishModel` + `groupImageAssembly` 生成模型
   - 体素 key 用 `${x},${y+2},${z}`，`finishModel(cells, w, h+2, d)`，**基底与主体同宽**（`finishModel` 自带的外圈底板会悬空不连通）

## 3. 验收样板（`lib/brick-reader.test.ts`）

三块合成样板，砖块布局已知，可直接判定"读对没读对"：

| 样板 | 内容 | 现状 |
|---|---|---|
| 硬接缝 | 5 块砖 + 4 薄板底板，接缝为深色硬线 | ✅ **逐块精确**（位置/尺寸/颜色） |
| 光照不均 | 6 凸点，横向渐变 30% | ✅ 比例正确、能切分 |
| **软光弱接缝** | 7 块砖，渐变 18% + 接缝只比砖面深 18% | ❌ **5/7** |

真图（神庙正面渲染，700 px 宽）：手填 48 凸点 → 读出 253 块 → 成品 2840 块 → 0 重叠 / 0 缺支撑 / 完全连通。

## 4. 卡住的点（下一步就这一件事）

软光样板的失败模式已经精确到一句话：

> **异色砖之间的接缝能读到，同色砖之间的接缝读不到。**

读到的：`0/9/8/3  0/6/8/3  0/3/6/3  6/3/2/3  0/0/8/3`（顶部与中部各丢一条 x=4 的接缝）
样板画的：顶部 4 块 2 凸点宽（接缝在 x=2/4/6）、中部 2 块 4 凸点宽（接缝在 x=4）

已打出的分数：软光样板该段为 `0,0,0,1,1,1,0,0,0`，阈值 4.0。

**矛盾点**：按样板几何，接缝画在 `px+pw-1/-2`，网格线在 `columnAt(k)`，±2 px 窗口应当覆盖，分数应≈32 而不是 ≈1。所以要么是我对"网格线落在哪一列"的假设有错，要么接缝在样板里没真的画出来。

### 已经排除的（2026-08 更新）

1. **样板没问题**：直接读像素，x=30-31 是接缝（暗度 114），砖面 72-77，对比度 40 —— 同色接缝确实画出来了。
2. **不是窗口太小**：`joint()` 的最暗窗口已从 ±2px 加宽到 ±0.3 凸点（±4px），软光样板仍是 5/7。
3. **不是颜色差异**：底排读到的唯一接缝是 x=6，而 x=4 那条**异色**接缝（SAND|DARK）也没读到 —— 所以"同色才丢"这个早先的结论也不成立。
4. 遮罩包围盒正确（left=8，与样板 margin 一致）。

→ 剩下的嫌疑集中在**分段/行逻辑**：`cutsRow` 的最小段高合并、以及 `boundary`（整行都暗）跳过规则，可能把某段的行区间算错，导致段内扫描的行根本不是接缝所在的行。

### 最新一组数据（2026-08，决定性）

软光样板底排（4 块：SAND,SAND,DARK_SAND,SAND，接缝在凸点 2/4/6）实测：

```
BAND 6..9 (rows 37..51) limit 12.7 scores 0,0,0,0,0,1,51,2,0
JOINT x=32 rows 37..51 skipped [49,50]   → 分数 0
JOINT x=80 rows 37..51 skipped [49,50]   → 分数 51 ✓ 唯一读到的
```

而**直接读像素**：同一排、x=30-31 的暗度是 **114**，两侧砖面 72–77（对比度 40）。也就是：
- 段的行区间（37..51）是对的，跳过的行（49,50 是横向边界）也对；
- 网格列 x=32 的窗口 28..36 **覆盖** x=30-31；
- 但 `joint(x=32)` 得 0，`joint(x=80)` 得 51。

→ 只剩一个可能：`darkness(30..31, 某行)` 返回了 **-1**（即 `mask` 在这几个像素上是 0，或行号落到了对象之外），于是该次取样被 `continue` 跳过。

### 根因已找到（2026-08，决定性打印）

对 `line = 32`（软光样板顶排）逐行打印 `at / darkness(30,at) / darkness(31,at) / mask[at*w+30]`：

```
at=8..19   mask30=0   d30=-1        ← 该排的主体从凸点 2 开始，x=30-31 在物体外
at=20,21   mask30=1   d30=d31=200   ← 整行都暗，是横向边界行，但 boundary=false（没被跳过）
at=22..    mask30=0   d30=-1
```

**根因**：`joint()` 的打分要求 ±半凸点处**两侧砖面都取到样**。当一侧落在物体外（空洞/边缘）时该行被 `continue` 跳过；而唯一在 mask 内的那两行又正好是横向边界行（且 `boundary` 规则没识别出来）→ 有效样本数 n=0 → 分数直接变成 0。
顶排之所以全丢，是因为它的砖从凸点 2 才开始，接缝正好贴在物体边缘。

### 修法试过两次，都回退了（第二次的关键教训）

第二次尝试：把打分改成"轮廓式"——每行在 ±1 凸点内取最暗值当接缝候选，在外侧取**最亮的可用像素**当砖面（这样一侧落在物体外也能打分），再拒绝"候选比砖面暗 1.6 倍以上"的整行，并要求足够多的行参与。

结果：**列接缝的问题没解决，行接缝先坏了** —— 硬接缝样板丢掉整条橙色砖（顶排），光照不均样板直接塌成一块。

**关键教训**：`joint()` 同时被用于**垂直接缝（段内）**和**水平接缝（段边界）**，两者的几何关系不同；把打分泛化成"轮廓式"虽然对贴边的垂直接缝成立，却破坏了水平接缝。下一次修改必须**把两条路径分开**（或者至少分别校准），而不是共用一套判据。

### 修法试过一次，回退了（重要教训）

按上述三条改过一版 `joint()`（一侧取不到样就用另一侧 + 绝对判据识别边界行 + 贴边不参与打分），结果是**两个硬接缝样板都挂了**（软光样板因为断言仍是放松版而"通过"，具有欺骗性）。已回退到改动前的状态：硬接缝逐块精确、装配通过、软光 5/7。

三个样板现在都被**钉了下限**（硬接缝 5 块逐块精确、装配用例通过、软光 ≥5），所以任何一次改动都必须三个一起看：软光从 5 掉到 4 会直接报错，不会再被放松断言掩盖。

教训：这块代码的三个用例互相牵制，**任何改动必须同时跑三个样板**，只看软光样板的"通过"会误判。回退版本已保存在 `lib/brick-reader.ts` 的 `joint()` 注释里（说明为什么保留 median+6 的旧判据）。

### 下一步的修法（已明确，不是再排查）

1. **一侧取不到样时用另一侧**，不要整行丢弃；
2. `boundary` 改为绝对判据：窗口内最暗值 ≥ 砖面暗度的 1.6 倍即视为横向边界行（现在是"该行平均暗度 > 中位数+6"，在低对比图里不灵）；
3. 两端贴边的接缝（砖块在物体边缘开始/结束）不要参与打分，改为**仅由轮廓决定**：轮廓边界本身就是分段边界。

**验收标准**：软光样板 7/7 且硬接缝样板保持逐块精确。

### 旧的第一步（打印什么）

在 `joint()` 里对 `line = 32` 的那次调用，逐行打印 `at`、`darkness(30, at)`、`darkness(31, at)`、`darkness(32, at)`、以及 `mask[at*width+30]`；跑软光样板（`facade(pieces, 8, 9, 12, true)` + `{ pitch: 12 }`）。这会把"是 mask 判定错了，还是取样坐标错了"一次分清。

```
left, right, columnAt(k) 对 k=0..8
每个 k 的 seam（±2px 最暗）、face（±半凸点两侧）
被判定为 boundary 的行号
```

再沿同一条接缝**直接读像素**（不经 `joint()`）：`x = columnAt(4)-1` 与 `x = columnAt(4)` 两列的平均暗度对比。两者一对照，立刻能分清是"样板没画接缝"还是"取样取错了列"。

若是样板问题 → 修样板（这是判据，不能带病）；若是取样问题 → 改 `joint()` 的最暗窗口或 face 偏移量。

**验收标准**：软光样板 7/7 且硬接缝样板保持逐块精确。

## 5. 试过并已否决的方案（别重复走）

| 方案 | 结果 |
|---|---|
| 阈值 = 该段中位数 + 0.45×(最大值−中位数) | ❌ 硬样板失败、真图 253 → 45 块。原因：一整排 1 凸点小砖的分段里，中位数本身就是接缝，两者无法区分 |
| Otsu 双峰分割 | ⚠️ 可用但更保守：真图 158 块（对比 25% 规则的 253 块）；软光样板同样是 5/7，说明**阈值不是软光的瓶颈** |
| 5×5 取色窗口 | ❌ 把树这种小特征一起抹掉，黑色面几乎没改善 |
| 用"真图读出多少块"当质量指标 | ❌ 误导：软光下**读得多很可能就是过分割**。只有真值样板可信 |

## 6. 踩过的坑（其他路线也适用）

1. **体素网格宽深取偶数**：奇数会留下 1 凸点窄条，任何砖都跨不过去，模型不连通
2. **`finishModel` 会给基底加一圈 1 凸点外沿**：若主体没有覆盖它，那圈砖悬空 → 多视图/图纸路线都改成"基底与主体同宽"
3. **内部体素索引 0 = 白色**：把"未取色"标记成 0 会让整个内部变白砖（真图上 4,761 块白砖的根因）。必须用 255 之类的哨兵值
4. **薄板间距不能取整**：`round(pitch × 0.4)` 在高立面上漂移近半格
5. **垂直接缝的 ±3 行边距会切掉接缝行**（接缝画在砖块下缘）；正确做法是跳过"整行都暗"的横向边界行
6. **参考图配色**：未见表面不要采深色开洞（会让背面变黑）；照片阴影应整体并回主材质，近黑按深灰处理
