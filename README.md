# Brickform 积木工坊 · V10.1

本机运行的图片参考与积木设计工作台。V10 上传后默认自动生成通用轮廓立体或图片浮雕，输出真实零件预览、清单和逐块步骤；保留小鸭精细模式和旧版模板。图片不上传服务器，生成在浏览器 Worker 中执行；没有接入通用 AI 图片理解或神经三维重建，刷新会清空本次设计。

## 运行

Node.js 22.13+（推荐 24）。

```sh
npm install
npm run dev
npm test
npm run typecheck
npm run build
```

## 生成路径

### 通用图片（V10 上传默认）

- 上传 PNG、JPG、WebP，最长边采样至 128 像素，读取后自动生成。每次换图自动切回通用模式，避免把其他物品套进小鸭模板。解码或生成失败显示错误，并保留最后有效模型；已读取图片可调整参数重试。
- `imageTreatment` 根据透明度与边缘颜色一致性选择背景处理，这是背景启发式，不是物体语义识别。干净背景生成随轮廓变化的对称厚度；边缘复杂或均匀空白画面保留原图生成浮雕。完全透明图明确拒绝。用户可手动选择轮廓立体 / 图片浮雕、保留背景及去除强度。
- `generateImageDesign` 复用轮廓引擎与 10 种基础砖、薄板，加入两层交错底座和必要的同色支撑。背面和体积是推测，不声称从单张照片还原真实三维结构；人物、风景和复杂照片可生成保留画面的浮雕。
- 生成与检查在独立 Worker 中执行，结束后释放；超时或 Worker 错误可重试。V10.1 使用 Vite 的 `?worker&url` 资产导入和当前页面 HTTPS 地址解析启动路径，避免页面编译器把 `import.meta.url` 替换为构建机的 `file:///ROOT/app/page.tsx`，导致发布后 Worker 无法启动。默认 28 凸点、8 凸点厚度，支持 20 / 28 / 36 凸点与 4–20 凸点厚度。
- 将基础模型转换为完整 LDraw 位姿，按高度依赖分组，每组最多 12 块。真实几何预览、分层展开、逐块定位图、HTML、CSV、LDraw 使用同一份放置。底座与辅助支撑计入清单，可单独查看；通过零件连接、顺序、外包框重叠及整体连通检查后才应用模型。
- 通用说明书采用坐标数字增大方向，不沿用小鸭专属方向说明。结果说明始终显示实际采用的背景方式和轮廓 / 浮雕类型。

### 小鸭精细模式（V9 保留）

- `fitDuckImage` 从干净背景、红 / 橙嘴的小鸭侧面图测量主体、头部、鸭嘴和眼睛位置。按嘴部位置统一左右朝向，头部使用上部 32% 的主体像素，身体使用下部轮廓。黄色阴影归入主体，减少色斑。
- `roundedDuck` 用连续的测量值拟合头、身体和颈部椭球，单独构建嘴与尾巴；这仍是受限的小鸭重建语法，不是通用对象识别，背面为对称假设。
- 18 / 20 / 22 凸点基准，85%–115% 饱满度。先铺两层薄板，优先跨越接缝连接；内部用砖、外缘用薄板，表面阶梯先匹配左右对称的宽弧面及斜坡件，再补齐 1 × 2 窄弧面。不会参与后续连接的外露小薄板以同尺寸光面板替换，保留跨接整块薄板；仍保有体素台阶轮廓。胸前、颈前、额头、后脑和左右脸颊分别使用一块 88930 宽弧面，配套侧凸点砖和内部连接板；脸颊面板内收，上缘加连接板承托头顶。头顶优先沿同一方向铺设 93273 双向弧面，背部匹配 93606 长弧面，再用短曲面补齐残余区域；面板占据的体积在装配前从体素壳中移除。左右翅膀各用一块 88930 宽弧面取代原先两块 15068，分别通过四个侧凸点连接，内部连接薄板保证安装顺序；鸭嘴暴露部分用光面板收口。
- V8 在全局顶部曲面之后逐层识别头部下方的局部台面，补齐肩部、颈部和脸侧的短弧面；每次替换保留已安装曲面的占位，保持左右成对匹配。局部曲面替换会保护其他预定曲面下方的连接凸点，避免将承托层改成光面。未用于连接的外露顶面优先用一层薄板厚度的光面件封口，悬挑处保留完整跨接件。精细表皮可能增加零件数量，21 组参数的回归上限相应为 850 块。
- V9 对不再承接其他零件的直斜坡，使用底板、后排垫片和曲面件替换，保持总高度与底部连接不变；仍被其他零件使用的顶部凸点保留。孤立的左右对称转角用 49307 圆弧顶替换 1 × 1 光面板，中心高出一层薄板，替换前检查完整零件包围盒。默认示例使用 14 块圆弧顶，不把连续边缘变成波纹；图示与方向说明使用真实半圆轮廓。
- 不添加底座或外露支撑柱。无法跨接的局部体素会被裁减，裁减比例超过 12% 拒绝生成；该比例不是整体外观误差，也不包含曲面拟合改动。输出仍需通过完整装配检查后才进入工作台。
- 同一张实际小鸭参考图在默认参数下为 462 块、25 种零件 / 配色组合、39 步，约 9.3 × 14.4 × 12.8 cm。具体值由输入图及参数决定。默认示例的比例由这张参考图测量后保存，不执行在线推理。
- 新增零件的底部连接高度逐行定义：88930 为平底，93273 中间两排抬高一层薄板，93606 的后两排分别抬高一层、两层薄板；49307 是单凸点平底，圆弧半径为 10 LDU。内部空位与安装顺序使用相同数据，长弧面在下方垫高零件之后安装。新零件来自受限的 LDraw 官方库文件，不能据此保证每种配色都在售。
- `model.reconstruction` 记录方法、尺寸、饱满度及局部裁减比例。所有实际放置仍采用同一套 LDraw 位姿，驱动实时视图、BOM 和说明书。

### 小鸭部件模板（V3 保留）

- 用户明确选择小鸭结构，不能识别任意物体。参考图仅提取主要配色、红橙色嘴部候选，以及两档头身 / 身体比例；也可以完全手动设定。
- 用基础砖、薄板、弧面斜坡、45° 斜坡、光面板、侧凸点砖和圆形光面板组成六个部件：身体、翅膀、尾巴、头部、嘴、眼睛。
- 四组比例组合约 128–175 块（以实际生成值为准），不自动增加底座或支撑柱。
- 每个零件保留 LDraw 的平移、完整旋转矩阵、部件和步骤编号。侧装眼睛与翅膀使用真实侧凸点位置。
- `model.levels` 在此路径表示步骤索引，`brick.step` 是所属步骤；不能用安装高度替代搭建次序。
- 主预览默认显示完整作品，阅读逐块说明不再裁切主模型。主动选择「跟随拼装」或拖动进度时才显示已搭建零件；「完整作品」及部件筛选可直接恢复完整范围。镜头按当前可见网格的包围盒取景，避免单块零件缩成远处小点。
- 实时 3D 从自带的 LDraw 网格加载，不在用户会话中请求第三方零件资源。支持五个视角、部件单独查看、按搭建组分层展开与逐步搭建。分层按实际步骤排序，每次 6 组或全部展开，层间距可调，编号与说明书步骤对应；按部件筛选后只展开该部件所在的搭建组。展开只改变预览位置，不改变清单、LDraw 或说明书的真实坐标。
- V8 修复实例化网格中的镜像坐标转换：在顶点数据中转换 Y 轴并反转三角形顺序，实例矩阵使用保持方向的旋转和平移。避免外表面被剔除、错误露出底部空腔；普通零件和侧装零件共用相同变换。
- 检查保守外包框碰撞（排除曲面件背面合法凹槽）、顶部 / 侧面凸点与底部连接位置、安装次序、完整连接图。不是受力模拟或实物拼装证明。

### 通用生成复用的轮廓底层引擎

1. 图片缩放到最长边 128 像素，透明图片参考 alpha，从边界泛洪去除近似背景。
2. 映射到 20 / 28 / 36 凸点规模，以 8 mm 凸点间距、3.2 mm 薄板高度修正纵向比例。
3. 立体模式按轮廓距离估算厚度，浮雕模式使用均匀厚度。合并为 10 种基础砖和薄板。
4. 加入两层交错底座和必要的同色支撑；检查网格碰撞、下方承托与整体连通。
5. V10 将输出转换为完整装配，使用自带的真实零件网格及逐块说明书；旧版近似渲染组件仅保留兼容代码。不具有真实背面重建能力。

## 零件与导出

- 工作台、CSV、LDraw、HTML 说明书均由同一份已生成模型驱动。未应用的参数不会进入导出文件。
- LDraw 保留官方库编号、颜色、位置、方向及 STEP。库编号的 b 等后缀是形态版本，不等同于 LEGO 商店的设计编号。
- 小鸭与通用图片说明书均使用等轴测外形简图和逐块安装图，省略空腔，标出新增零件、坐标和安装方向；每组另有编号俯视图。
- HTML 可离线打开、打印或另存为 PDF。CSV 带 UTF-8 BOM。
- 没有完整的零件 / 颜色组合白名单、实时库存或价格。具体编号和配色必须在购买前核对，不保证仍在生产或在售。

真实几何来自 [LDraw.org Official Parts Library](https://library.ldraw.org/)，这是社区维护的零件库，与 LEGO Group 无关联。原始文件及作者信息保留在 `vendor/ldraw`；公开署名与授权在 `public/parts/ATTRIBUTION.txt`，使用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。网格由 Three.js LDrawLoader 解析并三角化。

更新受限零件库时运行 `node scripts/prepare-parts.mjs`，只从 LDraw 官方库下载缺少的文件，再生成 `public/parts/geometry.json` 与署名文件。日常构建不需联网下载零件。

## 代码入口

- `app/page.tsx`：工作台、图片读取、参数与导出。
- `lib/image-design.ts`、`lib/image-design.worker.ts`：通用图片处理策略、装配分组与后台生成。
- `lib/rounded-duck.ts`：侧面图特征测量、连续体积拟合、曲面匹配、内部连接与装配。
- `lib/duck-designer.ts`：参考图配色 / 比例、小鸭部件语法与搭建顺序。
- `lib/assembly-catalog.ts`：零件尺寸、原点、矩阵工具。
- `lib/assembly-validation.ts`：顶部及侧面连接、外包框检查。
- `components/assembly-viewer.tsx`：真实网格预览、视角、展开与部件查看。
- `lib/assembly-diagram.ts`：离线说明书简图及方向文字。
- `lib/brick-engine.ts`、`components/model-viewer.tsx`：保留的轮廓生成与显示。
- `lib/manual.ts`：两种模式的说明书、CSV 与下载。

## 验证与限制

34 项测试覆盖通用图片的非小鸭轮廓、透明图、复杂场景、细长图、分离主体、空白及非法输入、18 组图片 / 尺寸组合，以及通用逐块说明与导出一致性；原有测试覆盖网格外表面朝向、侧装位姿的精确坐标、同一身体内逐组分层与筛选，及完整预览与逐块焦点隔离、可见零件取景、窄弧面与光面收口，以及逐块可见顺序、稳定定位网格、侧装提示及说明书每页数量限制，并覆盖 17 项原有测试中的 21 组 V4 尺寸 / 饱满度参数、左右朝向归一、图片特征移动引起实际模型变化、空图与不适用输入拒绝，并覆盖原有轮廓模式、四组小鸭比例、实际参考图配色变化、侧向连接、错误连接 / 顺序 / 碰撞的拒绝，以及模型、LDraw、说明书和 CSV 的一致性。每个部件都有有限、完整的内置网格及来源信息。

`scripts/render-assembly.py MODEL_JSON OUTPUT_PNG [hero|front|side|back]` 可在本地从同一份网格独立渲染模型，含深度检测与零件边线，辅助检查几何外观；这不是浏览器 UI 测试。本轮未做浏览器截图或交互测试。物理稳定性、夹持力、抗倾倒与实物拼装仍未验证。

使用 Sites / Vinext，部署归属在 `.openai/hosting.json`；构建产物位于 `dist/`。

## 新手拼装引导

- 拼装页按组、按块浏览：零件准备清单、独立零件外形图、悬空待装零件、落点虚线、方向箭头、真实连接点圆环、常驻局部俯视字母数字定位、整组编号总览。凸点用有高度的圆柱简图绘制，2 × 4 零件可数清全部 8 个凸点。提供「怎么装」与「装好后」对照，局部地图沿用完整图的字母数字坐标。当前零件突出显示，实际承托件始终纳入上下文，远处零件省略。
- 只显示已浏览到的放置顺序，选择「跟随拼装」时，立体预览同步隐藏本组后续零件；默认完整作品不受影响。点“已装好”才记入本组确认数，直接跳转不会自动确认之前的零件。切换组别或刷新重置该组进度。
- 立体模型的离线说明书包含每组准备清单与定位图，随后每页最多 4 个逐块安装图。详细版页数较多，可优先使用在线引导；通用图片浮雕也使用相同的逐块离线说明书。
- `lib/build-instructions.ts` 提供共享的步骤、定位和简图；`components/build-guide.tsx` 为交互界面。图为说明用途的简化几何，不是底部空腔或安装运动的仿真。

`npm run build` 在打包后执行 `scripts/check-image-worker.mjs`：从实际页面产物提取并执行 Worker 启动表达式，检查同源 HTTPS 地址、被请求资产是否包含在发布目录，并执行该资产的生成与错误响应。该检查覆盖启动入口，不只是单独测试生成函数。
