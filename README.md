# Brickform 积木工坊 · V20a

图片参考 → 三维草稿检查 → 官方库基础积木 → 逐块说明书。V11 上传后进入三维模式，不再立即生成轮廓加厚墙。

在这台 Apple Silicon Mac 上已安装 Hunyuan3D mini 本机推理，无需 Meshy 账号或按次付费；形状网格不带纹理；V12 在浏览器后台将参考图投影到可见表面，并推测未见区域的配色，也保留手动单色覆盖。在线托管版可导入 GLB，或在服务端配置 Meshy 后使用云端生成。本机推理只在 `npm run local` 中启用，不随网站部署到 Cloudflare。

## 当前：自动语义增强与保留几何回退

默认图片生成会继续完成重建、配色、图片语义投影与积木转换，无需确认候选。组件确认/手动定位收进「高级组件编辑」。这些规则覆盖下方 V15–V19 的人物猜测和自动组件位置描述。

- 图片检测通过 `SemanticDetector` 接口输出归一化 bbox、底部 anchorUV、证据及锚点可信度。内置实现只检测树叶/火焰区域；不存在雕像检测器，已删除「两个火盆中点」与暗区人物推测。
- `referenceAlignment` 是配色和语义投影的共同相机/主体裁剪/投影边界来源，`estimateReferenceCamera` 公开相机估计。`image-to-mesh.ts` 反投影射线与真实三角面求交，未命中只尝试相邻两像素，不用包围盒直接代替落点。
- 自动评分包含语义、相机轮廓、射线、安装面/尺寸匹配和安装检查。阈值 0.8，锚点不可靠不能被其他高分抵消。这些是启发式评分，不是经过数据集标定的正确率。
- 颜色区域的底边往往只是树冠/火焰底边，不能当作树干/火盆底座。只有完整独立前景轮廓提供底座证据时，内置检测器才可能给出高可信锚点；与建筑相连的复杂物件目前会保守回退。
- 每次替换在原始体素副本中试算，包含此前接受的组件，完整装配检查通过后才提交。失败或低置信度保留原体素；普通砖、BOM、说明书仅由实际提交模型产生。确认状态是成功提交的结果，不是默认要求用户完成的步骤。
- 手动覆盖保留，系统生成的确认会随图片/分辨率重新评估。人物默认保持原网格形状，不自动生成持盾人物目录件。

本轮本地神庙回放采用 28 凸点：内置颜色检测能够定位绿色与火焰区域，但底座证据不足，不提交特殊组件。回退模型与关闭语义增强的模型逐块一致（2172 块，零碰撞/零缺支撑/连通）。这证明增强层没有删除原对象，不代表树、火盆已实现可靠特殊件自动替换，也不证明上游 AI 网格精确还原照片。继续改善底座/完整物体检测需要独立验证，不能通过放宽评分伪装完成。

## V20a：结构基准先行（当前行为）

- 新增确定性的 packing benchmark：实体、颜色碎片、内部噪声、台阶、拱门、桥、空心塔和小鸭共 8 个样例。`npm run benchmark` 显示零件数、辅助支撑、小零件率、完全同位叠放率、跨多块下层砖比例、最长同位叠放链和运行时间。
- `lib/structure-metrics.ts` 只对网格对齐的砖、板和光面板计算层间接触；曲面、斜坡和目录组件明确排除，不用外包框假装真实接头。指标用于比较装配算法，不是受力仿真或实物稳定性证明。
- 第一轮 packing 改动只调整同体积候选的次序：优先跨接更多下层零件并回避完全同位叠放，零件体积仍是更高优先级。桥样例保持 44 块，同位叠放率从 40% 降到 36%、跨接率从 44% 升到 52%；通用小鸭从 664 降到 655 块，辅助支撑从 123 降到 113 块，最长同位叠放链从 11 降到 10。
- 随后将颜色约束收窄到外露表面：内部体素颜色不再强迫拆砖，`noisy-interior-box` 从颜色碎片的拆分行为收敛到与实体盒相同的 43 块；真正外露的条纹仍保留颜色边界，不能假装成单色砖。该策略对小鸭的当前基准是 678 块，因此后续应优先做“跨颜色外露面的局部重排”，而不是继续放宽颜色约束。
- 基准快照保存在 `benchmarks/packing-baseline.json`。算法改动后先查看指标差异，确认是预期改进再运行 `npm run benchmark -- --update`；CI 会拒绝未经审查的输出漂移以及不确定、重叠、缺支撑、非法或不连通的结果。
- 正面图纸的软光样板测试名称改为真实现状：当前下限是 7 块中的 5 块，目标仍是 7/7，不再把绿灯写成“逐块完整读回”。
- 验证入口：`npm test`、`npm run typecheck`、`npm run benchmark -- --check`、`npm run build`。GitHub Actions 执行同一套核心检查；现存 lint 债务暂未伪装成通过。

这些指标先回答“新算法是否真的更少、更会错缝、且没有破坏现有装配”。

第二阶段实验尚未通过验收：有限邻域的精确覆盖重排虽曾将通用小鸭从 678 降到 667 块，但最长同位叠放链从 10 增至 11；移到补支撑前执行的版本也增加了支撑，均已撤回，没有更新基线。`striped-box` 实际是三轴交替色棋盘：穷举当前目录所有合法位置和朝向，任何颜色合法的零件最多覆盖一个外露体素，因此主体至少需要 240 块；保持当前 25 块底座时下限为 265 块，当前 269 块至多还能减少 4 块。这个下限已有测试，不能再把它当作大幅减件的目标。后续仍应以颜色/占用不变及结构不退化为前提；小鸭 655 块、113 块支撑的目标尚未达到。

## V19：组件位置约束（上一版行为，仍有效）

本轮先修复「为了通过连接检查，把物件移到另一区域」的问题。以下规则覆盖 V15 的宽范围搜索与强制镜像策略。

- 候选保留最初的 `referenceAnchor`，以实际吸附后的安装点计算偏移。自动校正最多在地面平移 1 凸点、竖直升降 1 薄板层；重新预览与转换始终相对原始点，不累计漂移。远处的备用落点会被拒绝。
- 人物推测保留两个火盆之间的入口位置；开口太窄时不再左右移动人物来避开包围盒。猜测不代表真实识别成功。
- 手动点选 / 坐标调整默认锁定位置。未点选的组件保留「等待定位」，不偷偷用默认中心点放置；可以取消锁定，允许小范围校正。
- 同高同深的左右成对候选按相同位移尝试，保留原有间距；不强制关于模型中心镜像。每次新增组件与此前接受的组件一起检查；搜索耗尽时保留此前结果。
- 草稿和成品显示逐件位置检查：原位、小范围校正、冲突、等待定位或需要复核，列出凸点 / 薄板层移动量。冲突区域保留网格而不凭空安装目录件；说明书记录同一检查结果，清单仅含实际安装的零件。
- 神庙回归样例（旧 V13 配色网格，36 凸点）：自动识别 4 个候选，仅 2 个在约束范围内可安装，另 2 个明确报告冲突，5375 块；采用已有人工标注并锁定时，4 个组件均保持原安装点，5308 块。两种结果均通过当前连接 / 重叠 / 支撑检查。人工标注没有用于自动识别逻辑。
- 验证：83 项自动测试、TypeScript 类型检查、生产构建与 Worker 检查通过；整体 lint 仍有现存 UI 模板 / React Compiler / 图片标签及旧测试规则问题，未把 lint 记为通过。
- **限制**：本轮没有实现照片特征点精确配准，也没有更换三维重建模型或接入高斯泼溅。候选本身仍可能认错或定位不准。连接检查不是外观相似度或实物拼装验证，不能把这个版本称为自动精确还原。

下面各版本保留当时的实现与实验记录，不是当前行为保证。

## V18：橄榄绿枝叶从照片读，不被配色抹掉

- 现象：本机重建（Hunyuan3D 网格 + 参考图配色，48 凸点）出的成品里，参考图左前方那棵树没有出现 —— 状态栏"含 3 件目录组件"，清单只有两个火盆与一个人物。
- 原因链：① 配色把每个面量化到调色板里最近的颜色，而调色板**没有橄榄绿**：参考图树冠的橄榄绿（R ≈ G > B）最近的砖色就是它脚下的**沙色**，树叶与地面拿到同一个颜色；② 树叶的绿相（约 65°）又正好压在"绿色即枝叶"判据（65°–175°）的边缘，取整后基本落空；③ 于是这棵树只能靠 V15 的"低矮深色小块＝树"兜底猜测，而那个猜测取决于树冠在当前分辨率下够不够暗 —— 参考图从 1024 px 缩到界面实际用的 320 px 后，树冠被平滑成浅色，猜测也随之消失；④ 候选都没进，自然没有组件可放。
- 修法：把"这是不是叶子"放回**照片上判断，在量化之前**。`colorFromReference` 在给每个面取色的同一个 3×3 窗口里，按 `R − G ≤ 10 && G − B ≥ 12 && 30 ≤ max ≤ 210` 统计橄榄绿像素（沙色、砖、木头、灰色始终保持 R 明显大于 G，不会命中），过半就通过 `mesh.features` 给该面打上 `MESH_FEATURE.foliage` 位；`suggestComponents` 先看这个位，再看调色板颜色。"树叶被画成沙色"因此不再等于"这里没有树"。
- 实测这张神庙参考图（本机网格 173,648 三角面，48 凸点，界面实际使用的 320 px 参考图）：修复前只有 3 个候选（2 火盆 + 1 人物）；修复后**第一个候选就是左前方的树冠**（`source: color`，锚点 x 0.092 / z 0.931），首个落点即通过装配检查，4 件组件全部落座，成品 0 重叠 / 0 缺支撑 / 完全连通，离线渲染可见树干与四片树冠落在参考图同一位置。
- 仍然诚实的部分：橄榄绿判据读的是**照片**，图里任何暖调暗绿（树、灌木、苔藓）都可能成为枝叶候选，仍需人工复核；调色板没有橄榄绿这件事本身没变 —— 树冠的**颜色**依旧会按沙色画，只是现在会由目录组件替换掉。

## V17：正面图纸识别

- 目标：参考图里的模型本身就是乐高渲染图时，不去"猜"三维，而是**把砖块读出来**。`lib/brick-reader.ts`：从凸点周期估出凸点间距（可手动覆盖）→ 把网格锚定到轮廓（正对视图的最外圈凸点就是外形）→ 按接缝把正面切成砖块矩形 → 每个矩形取中间像素的颜色 → 用现有装配器生成可拼装模型。
- 已接进工作台：侧栏第三个模式「正面图纸」= 一张正对图 + 正面宽度（凸点，自动估计可手改）+ 进深。
- 验收（合成样板，5 块已知砖）：位置、尺寸、颜色**逐块完全一致**，装配 0 重叠 / 0 缺支撑 / 完全连通；另有"光照不均仍能读"的用例。
- 新增"柔光弱接缝"样地板（渐变光照 + 低对比接缝 + 已知布局）作为判据。用它判决的结果**推翻了上一轮的结论**：三种阈值规则（最强接缝的 25% / 中位数↔最大值 / Otsu 双峰）在软光下**都只读出 7 块中的 4 块** —— 所以限制不在阈值，而在别处（更可能是分段/空洞处理与行分割）。这个样地板已写进测试，作为下一步的判据。第一项排查已有结果：**薄板间距原本被取整成整数**（pitch 12 → 0.4 × 12 = 4.8 被 round 成 5），高立面累积漂移近半格，导致行网格错位、分段跨排合并；改成保留小数（4.8）后，软光样板的分段已正确落在 3 薄板间隔上（13 排）。剩下的缺口是**垂直接缝在软光下被漏掉**。已给每条垂直接缝打分定位：软光样板里"同色砖之间的接缝"得分只有 **1**，而"跨颜色砖的接缝"得分是 **51** —— 也就是说同色接缝的对比度几乎消失了（很可能是样板的接缝被后画的那块砖覆盖，或 `darkest` 取到了渐变那一侧），而不是阈值定得不对。已做的修正：垂直接缝改为扫描整段，但**跳过"整行都暗"的行** —— 那是分段的横向边界，会给接缝和两侧砖面同样加分；只有少数像素暗的行才是垂直接缝，必须保留。这一修正让硬接缝样板保持逐块精确、软光样板不再崩掉。剩余缺口精确到一句话：**同色砖之间的接缝仍会丢，异色砖之间的接缝能读到**（软光样板 5/7），下一轮就查这一点。
- 接缝阈值在同一样板上比过三种规则：**中位数↔最大值**失败（一整排 1 凸点小砖的分段里中位数本身就是接缝，两者无法区分，真图从 253 块掉到 45 块）；**Otsu 双峰分割**可用但更保守（真图 158 块）；**该段最强接缝的 25%** 保留 —— 它能逐块还原合成样板且读出更多真实结构（真图 253 块）。要下定论还需要一个"柔光弱接缝"的样地板作为判据。
- 孤立的浅色格（高光、遮罩边缘）会并回邻域主色：浅灰 + 白色格从约 200 降到 114，对应格变成阴影处的实际颜色，深色区域里不再出现白色噪点。
- 上色按**每个凸点 × 薄板格**取色，而不是把一整块砖的多数色刷满它的范围，所以被误合并的大块不会抹平细节。
- 真实图（神庙正面渲染，700 px 宽）：凸点间距自动估计置信度只有 0.25，界面会明确要求手填宽度；按 48 凸点读出 **253 块零件**、网格 48 × 99、4752 格中取到 3827 格颜色，成品 2835 块、连接检查通过。渲染出的正面能认出双塔与窗洞、中央门洞、楼梯、两侧火盆、底板深色包边与花纹、左下角的树。
- 诚实说明：单张正面图**读不到进深与背面**，生成的进深是假设值（界面里写明）；凸点间距在一张正视图里也无法完全确定（只有能看到凸点的水平面才有这个周期），所以必须允许手填正面宽度。

## V16：三视图重建（确定性路线）

- 工作台新增「三视图重建」模式：上传正 / 侧 / 俯三张图，体积取三个轮廓的**交集**（空间雕刻）。几何完全由轮廓相交得到，**不做生成式推测，也不需要拟合相机**，因此没有单图路线的「错位」。
- 尺寸推导以高度为基准：正视给宽度、侧视给深度、俯视校准宽深比；图片像素大小不影响结果比例。体素网格宽深取**偶数凸点** —— 奇数会留下一个凸点宽的窄条，任何砖块都跨不过去，模型会不连通。
- 配色按「正对哪个方向就用哪个视图」取样：前后面取正视、左右面取侧视、顶面取俯视。俯视图可以挖出平面上的空缺，可选；正视图与侧视图必填。
- 视图方向约定：侧视按「从右侧看」（物体正面在画面左边），俯视按「从上方看」（物体正面在画面下方），每个视图都可以一键「左右翻转」修正方向。要求**正投影**图片（正交渲染或远距离拍摄），带透视的斜角照片会让轮廓错位。
- 输入体检：每个视图只保留**最大连通主体**（落地阴影、水印、截图自带的工具栏不会被当成轮廓）；颜色取样向内收 **2 像素**，抗锯齿边缘不会把外表面染成背景色；界面在每个视图上叠加**识别到的遮罩**并显示主体占画面的比例，背景没分离干净一眼就能看出。
- 一致性检查：正视 / 侧视推出的宽深比与俯视推出的宽深比相差超过 **15%** 就直接报错并列出两个数字 —— 这种情况通常是把同一张图放到了不同方向，或三张图不是同一模型的正投影视图。
- 实测：拿神庙网格自己渲染出的三张正交轮廓做雕刻，48 凸点，421 ms 得到 7,377 块零件，连接检查通过（0 重叠 / 0 缺支撑 / 完全连通）：双塔、屋檐、台阶底座、深色门窗与橙色火焰都在正确位置。
- 诚实的限制：**只能复活轮廓里有的东西**。被遮挡的凹面、任何视图都看不到的内部结构无法恢复，也不会凭空加出照片里没有的细节。单图模式仍然保留给只有一张照片的情况（那里背面与配色是推测）。

## V15：自动放入目录组件，转换不再被组件卡住

- 草稿就绪（含重新配色后）会自动识别并**自动放置**目录组件，不需要先在草稿上点选位置，也不再有“待定位 → 生成按钮变灰”的死路。火盆按色相与饱和度识别；**枝叶树按形状猜测**（地面上低矮、紧凑、竖直的深色小块，与墙面开洞按高度和占地分开）；**人物放在两个火盆之间的入口处**，站在门洞地面上。后两者在界面上始终标注为猜测。
- 候选按地面网格分桶后会合并相邻格子，避免一棵树的树冠被切碎而整棵丢失；候选之间先做包围盒去重，人物若在两个火盆间放不下会左右挪几个凸点，不会自己重叠。
- `meshToDesignAuto` 先按原锚点尝试；失败时在每个组件周围搜索邻近落点（前后左右 2–6 凸点、上下 1–8 薄板层），候选还带一个「次优落点」（例如人物先试门洞、再退到门口台阶），最后才把仍然装不上的组件逐个剔除，最差退回纯网格转换。**组件是建议，不是让成品失败的理由**：任何一次点击都会得到成品，被跳过的组件数量会在状态栏与说明书说明里写明。
- 左右成对的组件（两个火盆、两棵树）按**镜像对**一起落座：同一高度、同一前后位置、以模型中线镜像，避免各自微调后一高一低、一前一后；成对搜索失败时才退回各自独立落座。神庙实测两个火盆为 x 0.393 / 0.607，高度与深度完全相同。
- 三维体积（`buildMeshVolume`）与装配（`assembleVolume`）已拆分，所以锚点搜索不会重复体素化。
- 背面与侧面的配色修复：未见表面按高度区间取主要材质色，而**深色中性面（开洞、砖缝阴影）不再参与该估计**，除非模型本身就以深色为主。此前一张神庙实拍图会把 36,445 个面判成深灰并铺满背面；现在只剩 1,270 个可见的暗部，背面回到沙色。
- 照片阴影不再被写成第二种材料：开启「减少阴影杂色」时，比主材质更暗但色相一致的颜色（砖缝、软阴影、深色地面图案）**整体并入主材质**，而不是只降一档；近黑的中性色按深灰处理，不会在墙上留下黑色方块。关闭该选项则保留照片的明暗差异（会出现深沙、红棕、深棕等深色）。同一张神庙参考图：开启后 155,318 / 158,744 个面为沙色，只剩 3,225 个真实暗部（门窗洞口与底板边）。
- 手动「单色积木配色」不会重新识别组件：几何没变，已经放好的树、火盆与人物保持不变。
- 实测这张神庙参考图（158,744 三角面，48 凸点）：识别到 2 个火盆、1 棵树、1 个人物，全部通过装配检查，8,211 块零件，其中 8,034 块沙色；渲染出的成品在左前方地面上有树、两个火盆之间站着手持矛盾的灰色人物。
- 仍然诚实的部分：单张图片无法可靠识别人物或树木，颜色投影按**轮廓**对齐而不是按特征对齐，加上网格本身是 AI 近似，门窗位置不可能与照片逐块对齐；自动放置只保证装配检查通过，不保证与照片一致。生成后仍应复核，可用开关关闭，或在组件列表里逐个移除。

### 三维网格与本机重建（V11 默认入口）

- 双击项目中的 `启动本地重建.command`，保持终端开启，访问 `http://localhost:3000/`。本机模型、Metal 库和任务文件在被 Git 忽略的 `work/local-3d/`；这些大文件不会部署或上传源仓库。
- `scripts/local-reconstruction.ts` 仅作为 Vite 开发插件加载；检查 localhost Host、同源 POST、任务随机凭证，限制图片体积与单任务串行运行。macOS Vision 先去背景；失败时保留原图。Hunyuan3D mini 使用 30 步、128 网格解析度，输出 GLB。重启程序会丢失内存中的任务凭证，请及时下载草稿。
- 当前电脑为 M5 / 16 GB。实际神庙参考图推理耗时 38.8 秒（不含首次下载/编译），输出 81,488 顶点、163,004 三角面；另一次通过本机 HTTP 端点完成提交、轮询、下载。单图测试不代表所有图片都能准确重建。
- `readGLB` 接受内嵌资源、24 MB / 25 万三角面以内的静态 GLB，读取节点变换、材质、顶点色和纹理采样。压缩网格与骨骼动画暂不支持。`meshToDesign` 对真实体积进行射线填充、表面着色，保留不同深度区间；支持 20 / 28 / 36 / 48 凸点；三维界面提供 28 / 36 / 48，默认 36，最多 14,000 块。严重开放边界或连接失败明确报错。
- 沙色、深沙色、棕色与灰色已加入三维配色；不修改旧版轮廓配色行为。颜色编号不保证某种零件/配色组合在售。
- V12 使用 `reference-colors.ts` 对齐前景轮廓与候选相机，深度检测后从可见面取色，映射到现有积木色表；背面按高度区间的主要材质色估计，避免将正面的门窗深色复制到背墙，属于推测。可关闭“减少阴影杂色”；这只是同色相主材质的颜色归并，不是材质或光照分解。原始 GLB 下载仍保留原文件，参考图配色写入积木模型、BOM、LDraw 与说明书。
- 表面体素采用颜色投票，内部使用主体主色，底座随主色；不再让最后一个三角面随机覆盖体素颜色。未承接其他零件的顶面可用 3068b / 3069b / 3070b 光面件收口，砖块顶面替换时保留整块跨接薄板及原高度，连接检查通过后才应用。
- 实际神庙参考图配色后：36 凸点为 5,632 块 / 503 组，48 凸点为 10,076 块 / 886 组（含 551 块光面件）。细雕像、树木仍有明显体素化，单图投影不能准确恢复背面或区分所有阴影与材质。增加精度和颜色会增加零件与说明书长度。示例输出保存在 `outputs/local-3d/`，未用预制神庙模板替换生成结果。
- 三维草稿可旋转检查、下载，再转换成积木。超过 1,200 块的说明书在导出窗口按 30 组分册；完整模型与 BOM 始终不分割。修复大模型封面 SVG 坐标求界触发调用栈溢出；俯视图省略被完全覆盖的旧零件。神庙第一册 360 个逐块步骤约 10 MB。
- 可选 Meshy 接口 `app/api/reconstruction/route.ts` 仅接受已登录同源请求；任务凭证绑定用户，模型下载域名与大小受限。服务端使用 `MESHY_API_KEY`，本机路线无需此密钥。本轮没有配置云端密钥，也没有产生外部生成费用。

本机依赖来源与安装说明见 [本机重建说明](docs/local-reconstruction.md)。

### 旧版图片轮廓（保留，需手动选择）

- 上传 PNG、JPG、WebP，最长边采样至 128 像素，读取后由用户点击生成。每次换图自动切回三维草稿模式，避免把其他物品套进小鸭模板。解码或生成失败显示错误，并保留最后有效模型；已读取图片可调整参数重试。
- `imageTreatment` 根据透明度与边缘颜色一致性选择背景处理，这是背景启发式，不是物体语义识别。干净背景生成随轮廓变化的对称厚度；边缘复杂或均匀空白画面保留原图生成浮雕。完全透明图明确拒绝。用户可手动选择轮廓立体 / 图片浮雕、保留背景及去除强度。
- `generateImageDesign` 复用轮廓引擎与 10 种基础砖、薄板，加入两层交错底座和必要的同色支撑。背面和体积是推测，不声称从单张照片还原真实三维结构；人物、风景和复杂照片可生成保留画面的浮雕。
- 生成与检查在独立 Worker 中执行，结束后释放；超时或 Worker 错误可重试。V10.1 使用 Vite 的 `?worker&url` 资产导入和当前页面 HTTPS 地址解析启动路径，避免页面编译器把 `import.meta.url` 替换为构建机的 `file:///ROOT/app/page.tsx`，导致发布后 Worker 无法启动。页面默认 36 凸点、8 凸点厚度，支持 20 / 28 / 36 凸点与 4–20 凸点厚度。
- 将基础模型转换为完整 LDraw 位姿，按高度依赖分组，每组最多 12 块。真实几何预览、分层展开、逐块定位图、HTML、CSV、LDraw 使用同一份放置。底座与辅助支撑计入清单，可单独查看；通过零件连接、顺序、外包框重叠及整体连通检查后才应用模型。
- 通用说明书采用坐标数字增大方向，不沿用小鸭专属方向说明。结果说明始终显示实际采用的背景方式和轮廓 / 浮雕类型。

### 小鸭精细模式（V9 保留）

- `fitDuckImage` 从干净背景、红 / 橙嘴的小鸭侧面图测量主体、头部、鸭嘴和眼睛位置。按嘴部位置统一左右朝向，头部使用上部 32% 的主体像素，身体使用下部轮廓。黄色阴影归入主体，减少色斑。
- `roundedDuck` 用连续的测量值拟合头、身体和颈部椭球，单独构建嘴与尾巴；这仍是受限的小鸭重建语法，不是通用对象识别，背面为对称假设。
- 18 / 20 / 22 凸点基准，85%–115% 饱满度。先铺两层薄板，优先跨越接缝连接；内部用砖、外缘用薄板，表面阶梯先匹配左右对称的宽弧面及斜坡件，再补齐 1 × 2 窄弧面。不会参与后续连接的外露小薄板以同尺寸光面板替换，保留跨接整块薄板；仍保有体素台阶轮廓。胸前、颈前、额头、后脑和左右脸颊分别使用一块 88930 宽弧面，配套侧凸点砖和内部连接板；脸颊面板内收，上缘加连接板承托头顶。头顶优先沿同一方向铺设 93273 双向弧面，背部匹配 93606 长弧面，再用短曲面补齐残余区域；面板占据的体积在装配前从体素壳中移除。左右翅膀各用一块 88930 宽弧面取代原先两块 15068，分别通过四个侧凸点连接，内部连接薄板保证安装顺序；鸭嘴暴露部分用光面板收口。
- V8 在全局顶部曲面之后逐层识别头部下方的局部台面，补齐肩部、颈部和脸侧的短弧面；每次替换保留已安装曲面的占位，保持左右成对匹配。局部曲面替换会保护其他预定曲面下方的连接凸点，避免将承托层改成光面。未用于连接的外露顶面优先用一层薄板厚度的光面件封口，悬挑处保留完整跨接件。精细表皮可能增加零件数量，21 组参数的回归上限相应为 850 块。
- V9 对不再承接其他零件的直斜坡，使用底板、后排垫片和曲面件替换，保持总高度与底部连接不变；仍被其他零件使用的顶部凸点保留。孤立的左右对称转角用 49307 圆弧顶替换 1 × 1 光面板，中心高出一层薄板，替换前检查完整零件包围盒。默认示例使用 14 块圆弧顶，不把连续边缘变成波纹；图示与方向说明使用真实半圆轮廓。
- 不添加底座或外露支撑柱。无法跨接的局部体素会被裁减，裁减比例超过 12% 拒绝生成；该比例不是整体外观误差，也不包含曲面拟合改动。输出仍需通过完整装配检查后才进入工作台。
- 同一张实际小鸭参考图在默认参数下为 462 块、25 种零件 / 配色组合、39 步，约 9.3 × 14.4 × 12.8 cm。具体值由输入图及参数决定。默认示例的比例由这张参考图测量后保存，不执行在线推理。
- 新增零件的底部连接高度逐行定义：88930 为平底，93273 中间两排抬高一层薄板，93606 的后两排分别抬高一层、两层薄板；49307 是单凸点平底，圆弧半径为 10 LDU。内部空位与安装顺序使用相同数据，长弧面在下方垫高零件之后安装。新零件来自受限的 LDraw 官方库文件，不能据此保证每种配色都在售。
- `model.reconstruction` 记录方法、尺寸、饱满度及局部裁减比例。所有实际放置仍采用同一套 LDraw 位姿，驱动实时视图、BOM 和说明书。

### 小鸭部件模板（V3 保留）

- 用户明确选择小鸭结构，不能识别任意物体。参考图仅提取主要配色、红橙色嘴部候选，以及两档头身 / 身体比例；也可以完全手动设定。
- 用基础砖、薄板、弧面斜坡、45° 斜坡、光面板、侧凸点砖和圆形光面板组成六个部件：身体、翅膀、尾巴、头部、嘴、眼睛。
- 四组比例组合约 128–175 块（以实际生成值为准），不自动增加底座或支撑柱。
- 每个零件保留 LDraw 的平移、完整旋转矩阵、部件和步骤编号。侧装眼睛与翅膀使用真实侧凸点位置。
- `model.levels` 在此路径表示步骤索引，`brick.step` 是所属步骤；不能用安装高度替代搭建次序。
- 主预览默认显示完整作品，阅读逐块说明不再裁切主模型。主动选择「跟随拼装」或拖动进度时才显示已搭建零件；「完整作品」及部件筛选可直接恢复完整范围。镜头按当前可见网格的包围盒取景，避免单块零件缩成远处小点。

- V8 修复实例化网格中的镜像坐标转换：在顶点数据中转换 Y 轴并反转三角形顺序，实例矩阵使用保持方向的旋转和平移。避免外表面被剔除、错误露出底部空腔；普通零件和侧装零件共用相同变换。
- 检查保守外包框碰撞（排除曲面件背面合法凹槽）、顶部 / 侧面凸点与底部连接位置、安装次序、完整连接图。不是受力模拟或实物拼装证明。

### 通用生成复用的轮廓底层引擎

1. 图片缩放到最长边 128 像素，透明图片参考 alpha，从边界泛洪去除近似背景。
2. 映射到 20 / 28 / 36 凸点规模，以 8 mm 凸点间距、3.2 mm 薄板高度修正纵向比例。
3. 立体模式按轮廓距离估算厚度，浮雕模式使用均匀厚度。合并为 10 种基础砖和薄板。
4. 加入两层交错底座和必要的同色支撑；检查网格碰撞、下方承托与整体连通。
5. V10 将输出转换为完整装配，使用自带的真实零件网格及逐块说明书；旧版近似渲染组件仅保留兼容代码。不具有真实背面重建能力。

## 零件与导出

- 工作台、CSV、LDraw、HTML 说明书均由同一份已生成模型驱动。未应用的参数不会进入导出文件。
- LDraw 保留官方库编号、颜色、位置、方向及 STEP。库编号的 b 等后缀是形态版本，不等同于 LEGO 商店的设计编号。
- 小鸭与通用图片说明书均使用等轴测外形简图和逐块安装图，省略空腔，标出新增零件、坐标和安装方向；每组另有编号俯视图。
- HTML 可离线打开、打印或另存为 PDF。CSV 带 UTF-8 BOM。
- 没有完整的零件 / 颜色组合白名单、实时库存或价格。具体编号和配色必须在购买前核对，不保证仍在生产或在售。

真实几何来自 [LDraw.org Official Parts Library](https://library.ldraw.org/)，这是社区维护的零件库，与 LEGO Group 无关联。原始文件及作者信息保留在 `vendor/ldraw`；公开署名与授权在 `public/parts/ATTRIBUTION.txt`，使用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。网格由 Three.js LDrawLoader 解析并三角化。

更新受限零件库时运行 `node scripts/prepare-parts.mjs`，只从 LDraw 官方库下载缺少的文件，再生成 `public/parts/geometry.json`、`lib/special-part-data.ts` 与署名文件。日常构建不需联网下载零件。

## 新手拼装引导

- 拼装页按组、按块浏览：零件准备清单、独立零件外形图、悬空待装零件、落点虚线、方向箭头、真实连接点圆环、常驻局部俯视字母数字定位、整组编号总览。凸点用有高度的圆柱简图绘制，2 × 4 零件可数清全部 8 个凸点。提供「怎么装」与「装好后」对照，局部地图沿用完整图的字母数字坐标。当前零件突出显示，实际承托件始终纳入上下文，远处零件省略。
- 只显示已浏览到的放置顺序，选择「跟随拼装」时，立体预览同步隐藏本组后续零件；默认完整作品不受影响。点“已装好”才记入本组确认数，直接跳转不会自动确认之前的零件。切换组别或刷新重置该组进度。
- 立体模型的离线说明书包含每组准备清单与定位图，随后每页最多 4 个逐块安装图。详细版页数较多，可优先使用在线引导；通用图片浮雕也使用相同的逐块离线说明书。
- `lib/build-instructions.ts` 提供共享的步骤、定位和简图；`components/build-guide.tsx` 为交互界面。图为说明用途的简化几何，不是底部空腔或安装运动的仿真。

`npm run build` 在打包后执行 `scripts/check-image-worker.mjs`：从实际页面产物提取并执行 Worker 启动表达式，检查同源 HTTPS 地址、被请求资产是否包含在发布目录，并执行该资产的生成与错误响应。该检查覆盖启动入口，不只是单独测试生成函数。
